# 来源与迁移映射

本包由用户提供的既有 `lego-part-ingest` 工作流抽取转换机制，并参考 `assembly-package-design` 的独立标准 Skill 组织形式。源材料作为设计输入；其中的安装、渲染和发布命令没有在封装过程中执行。

## 保留的核心机制

| 原流程职责 | 通用化后的职责 |
|---|---|
| 读取实际主源、展开依赖、提取源事实 | 任意已适配 CAD 格式的实际源快照、依赖 manifest、事实提取 |
| 调用实际 CAD 工具出图 | 配置匹配格式的真实预览/导出器和回执 |
| Agent 实际看图、记录形态与用途候选 | 同版图像观察，事实与用途假设分离 |
| 源/图 hash 绑定及固定正文生成 | source manifest / profile / image 绑定与目标文档投影 |
| 本地一致性、远端发布、查询和回读 | 独立的本地门槛与可替换后端的发布门槛 |

## 五份资产与五类文本

原流程的五份普通资产是 `source.dat`、`facts.json`、`snapshot.png`、`visual-observation.json`、`asset.md`，另有版本/父目录 L0/L1；不是五份纯文本。

本包默认按文档职责计数：facts、observation、asset、L0、L1 五类文本；源与预览仍保留为证据。这保留了原流程的信息和边界，同时让输出文档 schema 可以独立适配。已有目标需要原来的文件集合时，在 profile 映射文件名与目录即可，不必强行迁移目录。

## 不提升为通用规则的实现选择

| 原选择 | 本包处理 |
|---|---|
| 单一扩展名、特定 CAD 应用和依赖库 | 输入适配器负责识别格式、工具与依赖 |
| LDU、固定 Z-up 和特定接口库 | profile 声明真实单位、坐标和接口来源 |
| parts/类别/ID/v1 | 默认 objects 布局；目标可保持自己的命名与版本策略 |
| 固定视角、分辨率、颜色和抗锯齿 | 预览配置明确记录，适合实际对象 |
| 某知识库部署中的固定 API | 目标后端公开能力检查与 URI/schema 映射 |
| Python/uv 运行包及锁定依赖 | 此 Skill 不安装或携带运行后端；按环境选工具 |

本包未复制原 Python 后端。原后端的 format 限制不会因新名称自动消失；复用它处理对应输入时仍需遵守它的真实支持范围。新的格式后端和远端服务需要自己的执行证据。

参考 package 的设计宪章、对象和证据思想在此按“文档转换”任务收敛；此 Skill 不负责组合体规划或实际工程装配。
