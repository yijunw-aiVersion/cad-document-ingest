# 可选发布与远端回读

本地文档生成不依赖知识库。用户要求入库且授权范围已明确时继续发布，无需重复确认。未要求发布时交付本地成果。

## 后端契约

profile 指定后端、namespace、文件到 URI 的映射、公开读写方式、摘要所有权、同步/索引状态检查和真实查询方式。先检查当前环境公开接口的真实支持能力，不假定某个产品或版本必然有指定端点。

文件源、图片和 JSON 保持原字节；L0/L1 属于检索投影。对于自动生成摘要的后端，保存首次原生生成正文与回执，再通过受支持的公开接口发布约定正文。若摘要不可编辑，可使用目标支持的独立摘要字段或文档映射；必须符合用户目标规范，不能标记未达到的格式门槛为通过。

## 写入与恢复

1. 本地验收通过后列出全批精确 URI、版本和预期哈希。写入前核查所有目标：不存在可创建，相同跳过，同版不同内容记录 conflict 并停止冲突范围写入。
2. 按后端能力使用幂等键、条件写入或单写入者。没有 CAS 的预检不保证并发安全；记录这一限制，避免并发写同一版本。
3. 保存逐调用结果。网络错误或未知写入结果停止当前写入尝试，记录 remote_unknown；恢复时先回读确认实际内容，再续传缺失项，不能盲目重发。
4. 仅更新本次对象及约定的父导航范围。默认不改变其他对象、全库统计或服务内部数据库。

## 完成门槛

- 回读全部必需文件并比较原字节 SHA-256。对于存储正文含服务元数据的摘要，按 profile 明确抽取/规范化正文再比较，不把任意不同文本当等价。
- 回读 L0/L1 和可选父导航，核查规定正文与当前版本链接。
- 检查后端提供的同步/索引状态，通过实际查询命中目标对象和版本，再回读命中的来源原文。
- 保存预期/实际哈希、目标 URI、检查方法和结果；只有所有规定远端门槛通过才写 published。后端不提供某项能力时记录 unsupported，按目标规范决定能否约定降级。

verify 类操作只检查不修复；发现漂移记录 invalidated。修复属于新的已授权发布操作，重新回读验收。

## OpenViking 映射示例

目标可以使用 `viking://resources/<namespace>/objects/.../<version>` 或既有工程路径，把源、预览、facts、observation、asset 作为普通资源，并在对象/版本层发布规定 L0/L1。具体工具名和接口以已连接服务为准。服务的原生生成摘要与本 skill 规定正文分别留存，不改受保护元数据。

这是一种目标适配，不是使用 skill 的前置依赖。
